# 步衡 WalkScope | 技术设计

01  系统架构与职责


## 01  系统架构与职责

平台采用Vue 3 / Vite前端与FastAPI服务端。百度地图浏览器SDK负责底图展示；地点和步行接口提供外部空间服务；Shapely / NumPy完成几何与数值处理；DeepSeek经服务端参与问答和报告改写。

| 层次 | 职责与输入输出 |
| --- | --- |
| 浏览器界面 | 输入地址和类别；呈现进度、点位、路线、图层与七组卡片；提交问题或修改要求并下载Word |
| FastAPI接口 | 管理地点与体检任务、报告读取、问答流和草稿接口；校验请求、页面UUID及一致性号 |
| 测算模块 | 组织POI检索和分类、实际步行测距、中心等时圈、设施服务区、覆盖与盲区、数量参考评分 |
| 报告与存储 | 保存测算报告JSON、完整baselines、页面sessions和卡片快照；来源校验通过后导出Word |
| 外部服务 | 区分浏览器百度AK、服务端百度AK与DeepSeek Key，按不同服务职责配置 |
数据处理顺序

中心点与类别 → 设施检索及进度 → 步行测距与服务区 → 保存报告 → 地图展示与事实提取 → 受约束草稿修改 → Word。地图与报告共用保存结果，报告文字修改不重新执行设施检索或测距。

保存结果与重新测算

打开保存案例时读取已有报告，可重复查看同一份空间结果。实际发起新体检时，服务端才组织外部地点及路径请求。报告草稿独立保存，用户调整文字不会覆盖测算报告。

当前存储采用本地文件和单进程工作方式，适合本地研究及演示。多人部署时需要继续补充鉴权、事务持久化、配额与审计。

02  空间数据与分析口径


## 02  空间数据与分析口径

保存报告包含中心、结果时间、分组、小类、POI、步行及覆盖几何。圈内数量、圈外覆盖候选和服务区分别记录，避免将提供覆盖的圈外设施重复计入圈内数量。

| 对象 | 技术含义 |
| --- | --- |
| 中心步行圈 | 指定中心点的15分钟步行范围估算，采用100米采样 |
| 设施服务区 | 从真实POI出发，以1000米实际步行距离为阈值，采样插值形成连续边界 |
| 覆盖与盲区 | 将各小类服务区与分析域进行几何运算，得到已覆盖及有证据支持的未覆盖部分 |
| 未知 | 证据不足或尚未充分核验的部分，与确认盲区分别保留 |
| 数量参考分 | 按圈内设施数量分档，与服务区覆盖比例采用不同指标口径 |
大小类关系

大类共同盲区采用组内小项服务区的组合结果；该组只要有任意小项提供服务，相应位置便不属于共同盲区。小类查询只使用自身保存几何，缺少证据时显示缺失状态，不从父级复制结果。

地图表达与后续核查

20米网格用于覆盖分析辅助，地图最终采用连续服务范围与统一点距的点阵。确认盲区和未知可以统一浅蓝表达，但文字和数据仍保留其含义。

同济样例45小项的未知比例均小于1e-8。实际设施使用还应核实POI分类、校园内部点位是否对外开放，以及服务时段、容量和人口匹配。

03  报告修改与数据一致性


## 03  报告修改与数据一致性

草稿记录report_id、source_hash、锁定事实和章节内容。读取与导出前核对来源摘要及事实一致性；模型返回结构化的章节替换段落或删除标记，校验通过后再写入草稿。失败时保留当前内容。

01  新页面读取完整初稿

页面初始化生成UUID，读取、修改和导出使用同一ID。新页从baselines载入完整章节；缺少基线时构建完整事实稿。

02  按指令更新本页草稿

第三至第五章允许正文改写、删除与恢复，固定范围、测算方法与数据附表受到保护。内部一致性号用于识别并发或过期请求。

03  按卡片快照导出

每份报告卡片保存其对应内容，Word导出读取该快照。用户继续修改后，早先卡片仍能导出其原有内容。

04  关闭与刷新

关闭再打开对话仍使用本页UUID。刷新生成新ID并恢复完整初稿，已有页面修改另存于sessions。

主要接口

GET /api/v1/checkups/{id}/draft
POST /api/v1/checkups/{id}/draft/stream
POST /api/v1/checkups/{id}/draft/export

服务端验证页面UUID，拒绝路径式非法ID。报告正文与Word均不显示内部修订编号，内部字段仅用于一致性校验。

04  安装、运行与复现


## 04  安装、运行与复现

环境采用Python 3.12和Node.js 24。后端依赖由requirements.lock.txt锁定，前端由package-lock.json锁定；仓库大样例先核验摘要再还原。

| 步骤 | 操作 |
| --- | --- |
| 还原样例 | python tools/unpack_offline_samples.py |
| 安装后端 | python -m venv .venv；激活后运行 python -m pip install -r requirements.lock.txt |
| 安装前端 | 进入frontend运行 npm ci |
| 配置服务 | 复制后端与前端.env.example，再按需要填写本机配置 |
| 启动服务 | 分别运行 python tools/dev.py backend 和 python tools/dev.py frontend |
| 回归检查 | python -m pytest -q；frontend中运行 npm test、npm run build |
| 离线自检 | python tools/verify_handoff.py |
配置与访问

后端默认8768端口，前端默认5173端口。打开前端后可载入同济保存案例；通过view=map、report=tongji-all7-small-updated-20261027及base参数也可直接指定案例与后端地址。

浏览器百度AK只用于地图SDK，服务端百度AK与DeepSeek Key仅放在服务端环境。未配置模型服务时，保存事实稿与Word导出仍可使用；自由文字改写需要有效模型配置。
