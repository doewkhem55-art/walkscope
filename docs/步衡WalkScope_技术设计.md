# 步衡 WalkScope | 技术设计

01  系统架构与职责


## 01  系统架构与职责

平台采用 Vue 3 / Vite 前端与 FastAPI 服务端。地图通过百度地图浏览器 SDK 展示；空间处理使用 Shapely / NumPy；模型问答和报告改写经服务端接入 DeepSeek。源码保持 app、frontend、contracts、tests 等现有结构，便于沿用测试和安装方式。

| 层次 | 职责与输入输出 |
| --- | --- |
| 浏览器界面 | 地址选择、任务进度、地图图层、设施路线、七组评分卡、统一报告对话、Word 下载 |
| FastAPI 接口 | 地点与体检任务、报告读取、问答流、草稿读取/修改/导出；校验请求与页面 UUID |
| 测算模块 | POI 检索与分类、实际步行测距、中心等时圈、设施服务区、覆盖与盲区、数量参考评分 |
| 持久化文件 | 保存测算报告 JSON；独立完整 baselines；页面 sessions 与卡片快照；缓存只用于本机运行 |
| 外部服务 | 百度地点及步行接口、浏览器地图 SDK、DeepSeek 文本服务；密钥分别配置 |
关键数据路径

中心点 → 设施检索与任务进度 → 步行测距及服务区 → 固定测算报告 → 地图展示 / 事实问答 → 受约束草稿 → Word。后半段报告编辑不重新执行设施检索或测距。

保存报告回放可绕过新增外部测算。底图展示仍依赖浏览器地图配置和网络；新的实际体检需要有效服务端百度 AK 与接口额度。

02  空间数据与未知区域


## 02  空间数据与未知区域

原始保存报告记录中心、时间、分组、小类、POI、步行及覆盖几何等信息。圈内设施用于数量参考评分；圈外候选可能对圈内提供服务，但不能被重复计入圈内数量。

| 指标/对象 | 解释 |
| --- | --- |
| 中心步行圈 | 指定中心点的15分钟步行范围估算，不等于完整行政社区 |
| 设施服务区 | 从真实 POI 出发，基于实际步行距离构建1000米连续等距线 |
| 覆盖 | 保存几何证据支持该小类服务可达的分析域部分 |
| 确认盲区 | 按当前保存证据判定未被本小类服务区覆盖的部分 |
| 未知 | 未充分核验或缺乏证据的部分；与确认缺失分开 |
| 数量参考分 | 按圈内设施数量分档；不是覆盖率、容量评价或法定达标率 |
展示一致性与证据边界

小类图层只使用自身保存测算几何。缺少小类证据时给出缺失说明，不借用父级结果充当完成。确认盲区与未知在地图上可统一浅蓝高亮，后台分类及文字说明仍保留不同含义。

当前同济补算样例45小项均为采样估算完成，未知比例小于1e-8。POI 可能存在错分类、未收录及校园内部不对外开放等情况，后续需要设施台账、运营条件与现场调查核实。

03  草稿修改与事实保护


## 03  草稿修改与事实保护

报告草稿与测算报告分开存储。草稿带 report_id、source_hash 和锁定事实；读取及导出前核对来源和事实一致性。模型仅返回允许编辑章节的结构化段落，服务端校验后才写入草稿。失败不覆盖当前稿。

01  页面初始化

前端为本次页面生成 UUID。读取、修改、导出均传递同一 ID；关闭对话窗口不更换 ID。

02  读取完整初稿

新页面从独立 baselines 读取完整报告；缺少基线则构建完整事实稿，不继承历史删章测试稿。

03  连续修改与快照

第三至第五章允许正文改写、删除与恢复；固定范围、方法及数据附表受到保护。以内部一致性号检查并发，卡片导出对应其快照。

04  刷新恢复

刷新生成新页面 ID，回到完整初稿。本页修改记录保存在本机 sessions，提交包不包含这些历史会话。

接口与约束

GET /api/v1/checkups/{id}/draft
POST /api/v1/checkups/{id}/draft/stream
POST /api/v1/checkups/{id}/draft/export

页面 UUID 由服务端验证；非法路径式 ID 被拒绝。当前原型使用本地文件与进程内锁，不等同于生产多人事务系统；对公网部署前应增加鉴权、持久化事务、配额和审计。

04  部署、配置与复现


## 04  部署、配置与复现

建议 Python 3.12、Node.js 24。依赖文件为 requirements.lock.txt 和 frontend/package-lock.json。以下命令均在源码根目录执行，前端命令另注明目录。

| 步骤 | 操作 |
| --- | --- |
| 还原样例 | 克隆仓库后先运行 python tools/unpack_offline_samples.py，按摘要还原保存数据 |
| 安装后端 | python -m venv .venv；激活后 python -m pip install -r requirements.lock.txt |
| 安装前端 | 进入 frontend 运行 npm ci |
| 配置 | 复制 .env.example 为 .env；frontend/.env.example 为 frontend/.env.local，再按需要本机填写 |
| 运行后端 | python tools/dev.py backend（默认8768） |
| 运行前端 | python tools/dev.py frontend（默认5173） |
| 验证 | python -m pytest -q；frontend 中 npm test 与 npm run build |
保存案例地址：
http://127.0.0.1:5173/?view=map&report=tongji-all7-small-updated-20261027&base=http://127.0.0.1:8768

配置边界

浏览器百度 AK 仅供 SDK 使用，应在服务商限制域名；服务端百度 AK 与 DeepSeek Key 仅放服务端环境。提交包不包含实际密钥、node_modules、虚拟环境、缓存或页面会话。

本机源码副本与GitHub Ubuntu全新环境均已通过：依赖安装、样例还原、后端825项与前端236项测试、类型检查及构建、离线自检。3项在线百度测试默认跳过。首次运行链接见提交清单及仓库README。
